# Pocketa Git Workflow Strategy

## Branch Naming Convention

### Main Branches
- `main` - Production-ready code
- `develop` - Integration branch for features

### Feature Branches
- `feat/feature-name` - New features
- `fix/bug-description` - Bug fixes
- `refactor/component-name` - Code refactoring
- `docs/documentation-type` - Documentation updates
- `perf/optimization-type` - Performance improvements
- `chore/task-description` - Maintenance tasks

## PR Strategy

### Small, Focused PRs
Each PR should contain:
- Single logical change
- Maximum 400 lines of code
- Clear, descriptive title
- Comprehensive description
- All tests passing
- No merge conflicts

### PR Categories

#### 1. Core Infrastructure
- Base repository system
- Design system tokens
- Responsive utilities
- Error handling

#### 2. Feature Implementation
- Onboarding flow
- Transaction management
- Category management
- Wallet management

#### 3. UI/UX Improvements
- Component library
- Animation system
- Theme system
- Accessibility

#### 4. Testing & Quality
- Unit tests
- Widget tests
- Integration tests
- Code quality improvements

#### 5. Documentation
- API documentation
- Architecture docs
- Development guides
- Deployment guides

## Workflow Process

1. **Create Feature Branch**
   ```bash
   git checkout -b feat/feature-name
   ```

2. **Make Changes**
   - Write code
   - Add tests
   - Update documentation

3. **Commit Changes**
   ```bash
   git add .
   git commit -m "feat: add feature description"
   ```

4. **Push Branch**
   ```bash
   git push origin feat/feature-name
   ```

5. **Create PR**
   - Use GitHub PR template
   - Add reviewers
   - Link related issues

6. **Review & Merge**
   - Code review
   - Address feedback
   - Merge to main

## Commit Message Convention

### Format
```
type(scope): description

[optional body]

[optional footer]
```

### Types
- `feat`: New feature
- `fix`: Bug fix
- `docs`: Documentation
- `style`: Code style changes
- `refactor`: Code refactoring
- `test`: Adding tests
- `chore`: Maintenance tasks
- `perf`: Performance improvements

### Examples
```
feat(onboarding): add personalization screen
fix(transaction): resolve amount validation issue
docs(api): add repository documentation
refactor(ui): extract common button components
test(transaction): add unit tests for use cases
chore(deps): update flutter dependencies
perf(list): optimize transaction list rendering
```

## PR Template

### Title
```
[Type] Brief description of changes
```

### Description
```markdown
## Description
Brief description of what this PR does.

## Type of Change
- [ ] Bug fix
- [ ] New feature
- [ ] Breaking change
- [ ] Documentation update
- [ ] Performance improvement
- [ ] Code refactoring

## Changes Made
- List of specific changes
- Include file names if relevant

## Testing
- [ ] Unit tests added/updated
- [ ] Widget tests added/updated
- [ ] Integration tests added/updated
- [ ] Manual testing completed

## Screenshots (if applicable)
Add screenshots to help explain your changes.

## Checklist
- [ ] Code follows project style guidelines
- [ ] Self-review completed
- [ ] Code is properly commented
- [ ] Documentation updated
- [ ] No new warnings introduced
- [ ] Tests pass locally
```

## Branch Protection Rules

### Main Branch
- Require PR reviews (2 reviewers)
- Require status checks to pass
- Require up-to-date branches
- Restrict pushes to main

### Feature Branches
- Require PR reviews (1 reviewer)
- Require status checks to pass
- Allow force pushes

## Release Strategy

### Versioning
- Semantic versioning (MAJOR.MINOR.PATCH)
- Automated version bumping
- Release notes generation

### Release Process
1. Create release branch from main
2. Update version numbers
3. Generate changelog
4. Create release PR
5. Merge to main
6. Tag release
7. Deploy to app stores
